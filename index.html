    1 Introduction to Software Testing

    What is software testing?

    Software testing is the process of evaluating a software product to check whether it behaves as required and to find defects before users do. The International Software Testing Qualifications Board [ISTQB] (2023) explains that testing includes dynamic activities, where the software is executed, and static activities, such as reviewing requirements and code.

    Key terms. An error is a human mistake; it may introduce a defect (bug) into the code; when that code runs, it may cause a failure, a visible difference from the expected behaviour (ISTQB, n.d.).

    Objectives and importance

    • Find defects early. Faults found in requirements or design cost less to fix than faults found after release (ISTQB, 2023; Pressman & Maxim, 2020).
    • Show that requirements are met. Sommerville (2016) describes testing as a way to show developers and customers that the software meets its requirements and to reveal incorrect behaviour.
    • Support decisions and reduce risk. Test results give managers evidence for release decisions and lower the chance of failures in live use (ISTQB, 2023).

    Testing has limits: it can show that defects exist, but it cannot prove that none remain (ISTQB, 2023; Sommerville, 2016). Bertolino (2007) observed that testing is widely used in industry, yet is still largely ad hoc and expensive, so it must be done systematically.

    Role of testing in the SDLC

    The Software Development Life Cycle (SDLC) is the series of phases through which software is planned, built, delivered, and maintained. Testing has its own phase, but it is not only a final step: verification asks “Are we building the product right?” and validation asks “Are we building the right product?” (Sommerville, 2016). In agile and iterative models, testing is repeated in every iteration (ISTQB, 2023).

    2 Types and Techniques of Testing

    Tests can be grouped by level (when and how large a part of the system is tested) and by approach (how test cases are designed). ISTQB (2023) uses the term component testing for what many books call unit testing.

    Test levels

    1

    Unit testing

    Checks the smallest parts, such as functions or classes, in isolation; usually done by developers (Pressman & Maxim, 2020, Ch. 19).

    Example: a GST function given 1000 at 18% must return 1180.

    2

    Integration testing

    Checks that tested units work together, especially at interfaces and in the data they exchange (Pressman & Maxim, 2020, Ch. 20).

    Example: a valid login returns the correct user record from the database.

    3

    System testing

    Tests the complete system against its requirements, including performance and security (ISTQB, 2023; Sommerville, 2016).

    Example: search, add to cart, pay, and receive an order e-mail.

    4

    Acceptance testing

    Lets the customer or users decide whether the system meets their needs; a common form is user acceptance testing, or UAT (ISTQB, 2023).

    Example: staff try a new admission portal with real forms.

    Test approaches

    3 Testing Workflow and Best Practices

    The test workflow

    1. PlanSet objectives, scope, and approach
    2. PrepareAnalyse, then write test cases and data
    3. ExecuteRun tests; compare actual and expected results
    4. ReportLog defects; track them to closure
    5. CompleteSummarise results and lessons

    These stages follow the main activities of the ISTQB (2023) test process. A test case holds preconditions, inputs, and expected results (ISTQB, n.d.). A defect report gives an ID, title, environment, steps to reproduce, expected and actual results, and severity (ISTQB, 2023).

    Regression testing

    Re-running earlier tests after a change to confirm that nothing that worked before has broken (ISTQB, n.d.).

    Automation testing

    Tools such as JUnit, pytest, or Selenium run repetitive tests quickly. Automation needs setup and upkeep, so teams must choose what to automate (Garousi & Mäntylä, 2016).

    Best practices

    • Test early; review requirements before coding (ISTQB, 2023).
    • Link each test to a requirement.
    • Test high-risk features first (ISTQB, 2023).
    • Include boundary and invalid inputs.
    • Automate stable, repetitive tests.
    • Refresh tests, as old tests find fewer new defects (ISTQB, 2023).

    4 Conclusion and References

    Software testing is a planned activity that finds defects and builds confidence in quality. It spans the whole SDLC, works at four levels, uses black-box and white-box designs, and is run through a clear workflow supported by automation.

    Key takeaways

    Test earlyEarly defects are cheaper to fix.
    Four levelsUnit, integration, system, acceptance.
    Two approachesBlack-box and white-box.
    Report clearlyPrecise defect reports save time.
    Automate wiselyBest for repeated regression tests.
    Never “bug-free”Testing cannot prove zero defects.
